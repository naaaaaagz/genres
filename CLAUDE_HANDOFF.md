# GENRES site — handoff to Claude (2026-09-12, session 5)

## Session 5 — replaced decade rings with a topology-driven radial layout

After sessions 2-4 (all decade-ring-based patches), the user's verdict was "you basically delivered something worse" and the project was handed to Codex for a bit (see `CODEX_HANDOFF.md`). The user then came back with a fundamentally different layout instruction, paraphrased: forget concentric era rings entirely; radius should mainly come from "X came from Y, so the two are one step apart with a connector," chronology should only be a loose secondary nudge, and the three priorities in order are (1) direct parent→child connections should not cross each other, (2) the center should not be empty, (3) each Area blob should read as a compact, rounded "bean," not elongated/squiggly/twisted. They also asked for Area/sub-area labels to sit on the edge of their blob, in distinct colors.

This was a structural rewrite of the radius axis, not another patch. What changed in `src/layout.js`:

- **Generation replaces decade as the radius axis.** For every node, a same-category-only parent link (`catParent` — `n.parentNode` but only kept if it's in the same top-level Area) builds a forest per Area. `assignGen` walks each forest from its roots (nodes with no same-category parent — either true roots or ones whose real parent sits in a different Area) and gives every node a `gen` (0, 1, 2, …). The old global `decades` list and `byDecade` map are still computed, but now only feed a *soft* per-node `chronoT` (0–1 position in the full decade timeline) used as a small tie-break/nudge, never as the primary axis.
- **The main placement loop now iterates `gen` (0..maxGen) instead of `decades`.** Structurally this is the same per-category / per-sub-sector / track-packing machinery as before (`boxAt`/`overlaps`, the confined↔full continuous sub-sector interpolation from session 4), just keyed on generation instead of era. Radius still only ever grows monotonically as `gen` increases (`radius = maxOuter + 14` after each generation), so a node's same-category parent is always at a smaller radius than the node itself — i.e. the connector between them is a short, mostly-radial hop, which is what made most direct parent→child edges stop crossing anything (no algorithmic change was needed in the edge router itself — it just has far less untangling to do now).
- **Why this fixes "empty center":** most Areas' true roots (foundational, no-same-category-parent genres) vastly outnumber what a single "ancient/medieval" decade bin ever held — e.g. Latin has 22 gen-0 roots, Folk has 33, African 22 — so gen 0 is naturally well-populated for nearly every Area, instead of forcing all 21 Areas to share one nearly-empty innermost ring. Starting radius was also dropped from 150 to 90 since there's no era-bin geometry forcing a larger minimum.
- **Why this fixes "bean-shaped, not elongated":** each Area's radial extent is now only as deep as its own genealogy actually is (`maxGen` per Area ranges from 2 for Latin/Chiptune/Techno/Trance up to 7 for Classical), instead of every Area being stretched across the same dozen-or-so global decades regardless of how much real lineage depth it has. Verified visually — see below.
- **Labels moved to the blob edge.** `addAreaLabel` no longer anchors at the busiest decade cluster (roughly the blob's middle); it now anchors at the Area's fixed sector mid-angle (or the sub-sector's mid-angle for a Secondary Area) at that blob's true outer radius plus a small pad (`blobOuterRadius`/`edgeAnchor`), then still runs through the existing collision-avoiding `placeLabel` spiral search. Secondary-area label hue offset was also bumped from +14° to +42° from its parent Area's hue for a more distinctive color, per the user's ask.
- Removed the concentric decade-ring SVG guide circles and the per-ring decade-number labels entirely (`bands`/`.rings`/`.ring`/`.decade` machinery) — they represented global era rings, a concept the user explicitly asked to drop, and would have been actively misleading once radius stopped meaning "decade."

Verified after `node build.js` + `node measure.js index.html`: `maxR` 4716 (down from 6062 — noticeably more compact, not larger, despite dropping the era-ring structure), `worldW/H` 9553 (down from 12348), `routeFailures: 0` (down from 2), `innerVoidRadius` 224 with `voidShareOfRadius` only 4.8% of the radius, `cardOverlaps: 0`. Then — since this project's history is full of "metrics were clean but the user hated it" — actually looked at zoomed screenshots of every Area the user called out plus the two previously "mangled" sub-areas (Trance, Latin, Jazz, Classical, Jamaican, African, Chiptune, Downtempo, Psytrance, Experimental, Rock, Soul/R&B, Ambient-sub, Dubstep-sub): all read as clean, smooth, non-twisted, non-crossing blobs. Latin and Jazz in particular (the "unacceptable" ones from session 3) are now compact ovals with no criss-crossing. This is the first session where both the automated metrics and an actual visual check agree the shapes are good — but this is still only my own visual read, not the user's; treat it as promising, not as confirmed until they say so.

One deliberate interpretation call worth flagging: the user's phrasing "X genre came from Y genre, so Y is going slightly outwards from X" reads, taken completely literally, as the *opposite* of their own stated general rule ("further from center = newer"), since "X came from Y" means Y is the older/ancestor genre. This implementation went with the general rule and the pre-existing codebase convention (`n.parentNode` = the older/originating genre → smaller radius; `n` itself, the newer descendant → larger radius), on the assumption the specific sentence was a wording slip rather than a deliberate reversal. If genres now look like they're radiating the wrong direction (children closer to center than their own predecessor), that single sentence is the place to revisit — everything else in the design is direction-agnostic and would still work with `assignGen`'s direction flipped.

## Session 4 — fixed remaining sub-area pinching (Ambient, Dubstep)

After session 3 removed cross-category borrowing, the user flagged that some sub-area blobs (Ambient inside Experimental, Dubstep inside Breakbeat) were still "mangled" — thin, snake-like, with a sharp bend/pinch partway along. Root cause: within a category, each decade's sub-area placement still made a hard binary choice per decade between its own confined sub-sector and the parent's full sector (`if(confined&&totalNeed<=confCapacity*.85)se=confined;else se=fullSe`). Two adjacent decades could land on opposite sides of that 0.85 threshold, so the sub-area's angular bounds would jump abruptly from narrow to wide (or back) between consecutive decades — exactly the kind of discontinuity that produces a visible elbow/pinch in the smoothed contour, just confined within one category now instead of spanning across categories.

Fix: replaced the binary switch with a continuous one. `overflow=max(0,totalNeed/confCapacity-.8)` and `t=min(1,overflow*.7)` now blend the sub-sector's angular bounds smoothly between `confined` (t=0) and the parent's `fullSe` (t=1), so bounds widen/narrow gradually in proportion to actual need instead of jumping. Also bumped the sub-sector sizing basis from `ownPeak*.4` to `ownPeak*.55` (a modest increase, not full weight — full weight alone was tried and caused `maxR` to balloon from ~6039 to ~10800+ without fully fixing the shape, since the real problem was the discontinuity, not the sizing). Re-verified: `maxR` 6062 (essentially unchanged from session 3), `cardOverlaps: 0`, 0 label overlaps, `routeFailures: 2` (still within the documented tolerance). Ambient and Dubstep are now smooth curved ribbons with no sharp bends — visually confirmed via zoomed screenshots.

If a sub-area still looks pinched in a future session, don't reach for a third binary tier — tune the `overflow`/`t` slope constants (currently `-.8` offset, `*.7` multiplier) or the `ownPeak` weight instead, since any hard threshold reintroduces the same discontinuity.

## Session 3 — fixed a real regression from session 2

Session 2 (below) introduced a "borrow an idle neighboring sector" fallback to shrink the empty center. That fallback is what caused the user's next report: Area/sub-area blobs criss-crossing, twisted, and stretched way outside their own wedge (Latin and Jazz were the worst examples; Pop and Soul/R&B were "almost great" since they rarely needed to borrow). Root cause: a sparse decade could borrow angular space from a distant, unrelated sector, and since the contour connects consecutive decades' angular envelopes with smoothing, one wildly-displaced decade sample dragged the whole blob into a long twisted arc through other Areas' territory.

Fix: removed `borrowedRange` entirely. The main placement loop now only chooses between a sub-area's own confined sub-sector and its parent Area's full sector — never anything outside the Area's own fixed sector. This is safe (no more "Unable to pack" risk) because the packing loop already adds more radial tracks when a sector is tight, and a fixed angular span covers more linear distance at a larger radius — so any amount of content eventually fits inside its own sector, just by stacking deeper rather than reaching sideways. Trade-off: `innerVoidRadius` and `maxR` went back up (roughly to where they were before session 2's shrink — 353 and ~6039 respectively) since the borrowing trick is gone; the user didn't re-raise the empty-center complaint this round and explicitly prioritized eliminating the distortion, so this trade was made deliberately. If a future task revisits the empty center, do NOT reintroduce cross-sector borrowing — instead look at growing ring thickness for sparse early decades globally, or reducing padding, rather than letting one Area reach into another's space.

Also this session: removed the `border` from `.area-label`/`.secondary-label` (kept the background pill), roughly doubled both label font-size formulas, and replaced the naive "anchor at busiest-decade-cluster" label placement with a real collision-aware placer (`placeLabel`): it measures the label element, then spiral-searches outward (rings at 40/70/105/…640px, 20 angles per ring) for a position that overlaps neither any node card (12px pad) nor any previously-placed label (26px pad), falling back to the raw anchor only if nothing clears. Verified via a DOM audit script: 0 label-label and 0 label-node overlaps across all 32 labels. Also reworked the loading-screen text transition: was a 1.5–2s interval with a plain opacity cross-fade; now a 0.5–0.6s interval with a vertical scroll (translateY + opacity, ease `cubic-bezier(.4,0,.2,1)`, ~230ms out then in) inside a `.loading-text-wrap` with a `mask-image` gradient so text fades to nothing at the top/bottom edges of its slot rather than cutting off hard.

Re-verified after all of the above: `cardOverlaps: 0`, `routeFailures: 1` (one acceptable fallback edge, within the project's documented tolerance), no console errors, 0 label overlaps. Rebuilt via `node build.js` and committed to `C:\gpt\genres` (`src/layout.js`, `src/shell.html`, `index.html`).

## Session 2 — what changed

The user reported: overlapping/twisted sub-area blobs, blob "chokepoints" (Trance cited as the target quality bar), a too-empty diagram center, equal angular slices per Area regardless of size, no adjacency/affinity ordering of Areas, plain straight-line blob inner edges, missing Area/sub-area titles, weak or hallucinated region flags, and a blank 10–15s load with no feedback. All were addressed without touching the fixed-sector invariant below:

- **Sub-area blob overlap/chokepoints (fixed)** — root cause was track-overflow wraparound to the wrong start angle. Rewrote sub-area placement to give each Secondary Area its own nested fixed sub-sector inside its parent Area's sector, with a 3-tier capacity fallback per decade: confined sub-sector → full parent sector → borrow an idle neighboring sector (`borrowedRange`). Verified via zoomed screenshots (Experimental/Ambient, Trance, Breakbeat/DnB) — smooth, non-crossing contours throughout.
- **Empty center (reduced)** — was a genuine geometric constraint (too little circumference near r=0 for sparse early-era content even with a "fair" angular share). The same borrowed-range mechanism plus merging a duplicate `idm`/`IDM` secondary-value casing bug cut `innerVoidRadius` from 353→96 and overall `maxR` from 5879→~5087 (13–16% smaller world).
- **Non-uniform Area sectors** — `areaDemand` exponent changed from `sqrt` to `^0.58` for more contrast between big and small Areas' angular share.
- **Adjacency/affinity ordering** — generalized nearest-neighbor + 2-opt ordering (`chainOrder`/`cycleScore`/`twoOptImprove`) now drives both the top-level Area order (by inter-Area link weight plus an `electronicKin` affinity bonus keeping electronic genres clustered) and each Area's internal sub-area order.
- **Organic inner edge** — `contourPath` now inserts a symmetric "root taper" (two interpolated points per side blending toward the first ring's midpoint) so blobs funnel into a rounded apex near the center instead of a straight radial edge.
- **Area & sub-area labels** — every one of the 21 main Areas and all 11 Secondary Area contours now has an on-page title, placed at the busiest decade cluster of its node set (`labelAnchor`/`addAreaLabel`). Secondary-area labels are mapped through a `secondaryDisplay` table so the raw sheet codes (`dnb`, `ukgrime`, …) render as proper names (Drum & Bass, UK Grime, …).
- **Flags** — `eu.svg` now has an accurate outline of continental Europe (Natural Earth 110m boundaries, Svalbard/French Guiana clipped out as unwanted overseas fragments) behind the existing 12-star ring. `africa.svg` and `asia.svg` (used for the "South Asia" region) were replaced with real coastline-derived outlines (previous versions were hand-drawn/hallucinated approximations). Two new region icons were added and wired into `regionIcons` in `layout.js`: `caribbean.svg` and `latinamerica.svg`, both real geography (island arc / Mexico–Central–South America), each with its own improvised color palette since no universally-recognized single flag exists for either region. All geometry was generated from the `world-atlas` (Natural Earth) dataset, not hand-drawn — nothing here is invented coastline.
- **Loading screen** — was a blank page for 10–15s. The whole layout script now runs inside a double `requestAnimationFrame` so the loading screen paints immediately on load. Replaced the single spinner ring with a 3-ring counter-rotating SVG spinner and added the exact 7-message randomized-order, randomized-interval (1.5–2s) cycling text the user specified, cross-fading in/out. `#loading` now fades out over 0.5s (was 0.3s) once `#viewport` is ready.

## Invariants — do not break

1. Each main Area owns one fixed angular sector for the entire diagram. Never allocate or rotate Area sectors independently per ring/decade/generation; that previously produced visually random spiralling. Nested sub-sectors and the confined↔full interpolation both operate *inside* a given Area's already-fixed sector and never change a main Area's own boundaries.
2. (Session 5) Radius must stay monotonically non-decreasing in `gen`: everything at generation `g+1` must sit at a strictly larger base radius than everything at generation `g`, globally. This is what keeps a node's own same-category parent closer to center than the node itself, and it only holds because the main placement loop advances a single shared `radius` cursor once per generation (`radius = maxOuter + 14`), across all Areas together, before moving to the next generation. Do not go back to computing each Area's radius progression independently — that would reintroduce the "some Areas huge, some tiny, doesn't read as one diagram" problem the old per-decade-but-per-Area-independent designs had.
